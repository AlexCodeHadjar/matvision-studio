# План: MatVision Studio — только показ ковриков в реальном времени

Ветка: `realtime-only` (от `codex/mat-only-sizes`, версия 0.1.10). Целевая версия: **0.2.0**.

## Что показала проверка проекта

- Приложение уже написано не на Python: интерфейс и 3D — TypeScript + Three.js (WebGL2),
  оболочка и работа с файлами — Rust (Tauri 2).
- Python в проекте один: `src-tauri/cycles/*.py` — сценарии для Blender Cycles (режим Ultimate).
  Он уходит вместе с рендером, после чего **Python в проекте не остаётся**.
- Переписывать 3D-часть на Rust/WASM не нужно: кадр считает видеокарта, а не язык;
  переписывание дало бы месяцы работы без прироста скорости. Узкие места — в настройках
  сцены (см. ниже), и они устраняются рамками.
- Найденные проблемы производительности:
  - кадр перерисовывается 60 раз в секунду, даже когда на экране ничего не меняется;
  - качество по умолчанию — `ultra`: тени 4096², превью принта до 8192 px, окружение 2048 px;
  - нет ограничения на число пикселей кадра (4K-монитор × pixel ratio 2 = 33 Мп);
  - нет автоматического снижения нагрузки, если видеокарта не успевает;
  - в сборке лежат path tracer (≈370 КБ кода) и HDR-панорама 6,3 МБ, нужные только для «Фото».
- До изменений: типы чистые, 329 из 331 модульных тестов проходят. Два теста в
  `src/geometry/mat.test.ts` падали ещё до начала работы (не связаны с рендером).

## Этап 2. Жёсткие рамки оптимизации

Все числа — в одном файле `src/scene/budget.ts`; код обязан им подчиняться, тесты это проверяют.

| Рамка                         | Значение                                                       |
| ----------------------------- | -------------------------------------------------------------- |
| Целевая частота               | 60 к/с (16,7 мс на кадр)                                       |
| Порог снижения нагрузки       | кадр дольше 22 мс → разрешение кадра автоматически уменьшается |
| Нижняя граница масштаба кадра | 0,5                                                            |
| Простой (ничего не меняется)  | не более 2 кадров в секунду                                    |
| Пикселей в кадре              | ≤ 3,7 Мп (2560 × 1440); в детальном режиме ≤ 2,1 Мп            |
| Pixel ratio                   | ≤ 2                                                            |
| Карта теней                   | ≤ 2048²                                                        |
| Окружение (PMREM)             | ≤ 1024 px                                                      |
| Превью принта                 | ≤ 4096 px по длинной стороне                                   |
| Текстуры сцены                | ≤ 256 МиБ (оценка)                                             |
| Треугольники в кадре          | ≤ 2 000 000 (самый большой коврик со швом — около 1,61 млн)    |
| Снимок PNG                    | ≤ 4096 px по стороне и ≤ 8,3 Мп                                |
| JS-сборка                     | самый большой файл ≤ 1 600 000 байт, проверяется при `build`   |

Проверки:

- `tsc --noEmit` — без ошибок; `eslint .` — без замечаний.
- Модульные тесты: 346 из 348 проходят, из них 28 новых — на рамки (`src/scene/budget.test.ts`).
  Два падающих теста в `src/geometry/mat.test.ts` падали и до начала работы, я их не трогал.
- `vite build` и проверка размера сборки — в рамке.
- `cargo test` — 12 из 12, без предупреждений.

Что осталось непроверенным и нерешённым:

- Приложение не запускалось и на экране не проверялось: плавность, вид детального режима
  после снижения AO/SMAA и работа регулятора разрешения на реальной видеокарте не подтверждены.
- Эталонные скриншоты браузерных тестов сняты до изменений и требуют пересъёмки.
- Петли оверлока — главный оставшийся расход (до 1,4 млн треугольников вблизи). Упрощение их
  геометрии изменит вид шва, поэтому без просмотра на экране я его не делал.
- На мониторах с частотой ниже ~45 Гц регулятор сочтёт кадры медленными и снизит разрешение.
- ROADMAP, REALISM, RENDERING и другие исторические документы всё ещё описывают «Фото» и «Ultimate».

## Чего в этой работе нет

- Браузерные (Playwright) и нативные (WebdriverIO) тесты и замеры на видеокарте не запускаются:
  они требуют окна приложения и ручной приёмки.
- Установщик `.exe` не собирается и на GitHub ничего не отправляется без отдельной команды.
