# Renderer workflow 0.1.7: фактические возможности

0.1.7 вводит локальный **Ultimate prototype** для Blender 4.5 LTS/Cycles и расширяет Photo. Это промежуточный этап интеграции, а не визуально откалиброванная тройка renderer'ов. `.matvision` остаётся v2; Photo-настройки и путь Blender сохраняются отдельно от проекта (путь Blender — локально в браузерном хранилище приложения). Studio и Photo не требуют Blender.

| Возможность                   | Studio / Three WebGL2                     | Photo / three-gpu-pathtracer 0.0.24                             | Ultimate / Blender 4.5 Cycles prototype                                   |
| ----------------------------- | ----------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Размеры, скругление и толщина | Да                                        | Снимок геометрии Studio                                         | Да, отдельная округлая сетка; профиль края упрощён                        |
| Принт и размещение            | Да                                        | Запечённый принт                                                | Исходный файл и тот же UV inverse; требуется визуальная калибровка        |
| Ткань / резина                | PBR, карты                                | PBR, запечённый принт и рельеф нормалей                         | Базовые цвет и roughness; пользовательские карты не передаются            |
| Прошитый край                 | Геометрия петель                          | Развёрнутые петли                                               | Нет; явное предупреждение в UI                                            |
| Изгиб и анимация              | Да                                        | Текущая поза снимка                                             | Нет; плоский коврик и явное предупреждение                                |
| Свет                          | Текущие схемы; пять softbox при включении | HDR Poly Haven или студийная панорама + area light              | Один area light + локальный процедурный HDR; уровни пока не откалиброваны |
| Камера                        | Позиция, цель, вертикальный FOV           | Те же ракурс/FOV; опциональные фокусное, фокус и f-stop         | Позиция, цель, вертикальный FOV; без DOF                                  |
| Геометрический рельеф         | Нет                                       | Только при карте высоты, High+, не более 200 тыс. треугольников | Нет                                                                       |
| Шумоподавление                | Неприменимо                               | Выкл. или встроенный SmartDenoise на linear float target        | Cycles prototype пока без UI denoise                                      |
| Цвет                          | ACES Filmic → sRGB                        | RGBA32F linear accumulation → ACES Filmic → sRGB PNG            | Cycles float внутри процесса → AgX → PNG; соответствие не доказано        |

Photo Preview/High/Ultra/Reference используют соответственно 512/1024/2048/4096 проходов и длинную сторону 1920/2560/3840/3840 px. Сохраняется выбор вручную от 128 проходов. Число отражений остаётся **10** — повышение до 16 без измеренного выигрыша не выполнялось. Диафрагма по умолчанию выключена; фокусное расстояние совпадает с текущим FOV, пока пользователь не выбрал 35/50/70 мм. `PhysicalCamera` получает фокус в метрах из UI миллиметров. Рельеф доступен только при карте высоты; координаты вершины меняются в метрах после ограниченного subdivision снимка Photo. Он не меняет Studio, но тонкие волокна по-прежнему представлены картой нормалей.

`WebGLPathTracer.target` в установленной библиотеке создаётся как `RGBAFormat` / `FloatType`; линейные накопленные значения преобразуются только при показе через ACES и sRGB. SmartDenoise — поставляемый вместе с `three-gpu-pathtracer` GLSL spatial filter, работающий с этим float target перед tone mapping. Он не заменяет OIDN и не имеет albedo/normal auxiliary inputs. Нативный OIDN остаётся отдельной будущей интеграцией; данных для его трёх входов текущий backend не выдаёт. Выгрузка линейного EXR пока отсутствует.

Ultimate использует временный пакет `schemaVersion: 1` с размерами/камерой/UV-матрицей, копией нужного принта и render settings. Rust создаёт отдельный временный каталог, передаёт аргументы без shell, считывает status и PNG, убивает процесс при отмене/закрытии и удаляет каталог. Рендер запускается только по команде пользователя. Отсутствие Blender сообщает причину и не влияет на Studio/Photo. Сборка Blender не включена в установщик; пользователь указывает локальный `blender.exe` версии 4.5 LTS. Проверенная команда:

```text
blender.exe --background --factory-startup --python-exit-code 1 --python render.py -- scene.json result.png status.json
```

`AUTO` выбирает обнаруженный самим Cycles OptiX, затем CUDA/HIP/oneAPI либо CPU; явный выбор недоступного GPU переходит на CPU с сообщением в результате. Список берётся из `cycles` preferences, а не из названия видеокарты. Временный каталог и логи не показывают пользователю личные пути. Тестовая сцена `tests/fixtures/cycles-package-v1.json` и принт `tests/fixtures/landscape-grid.png` запускаются этой командой с путями, разрешёнными относительно пакета. Зафиксированные восемь эталонных сценариев находятся в `tests/fixtures/renderer-reference-scenes.json`: это параметры, не заявления об уже принятых изображениях. Часть сценариев (шов/изгиб) пока заведомо расходится с Ultimate.

Для калибровки нужно прогнать эти сцены на одной версии продукта, с фиксированными ракурсом, разрешением, принтом, устройством, числом проходов и версиями библиотек. Сначала сравнить силуэт и UV, затем серые/чёрные/белые поверхности, только после этого свет и exposure. Текущий профиль соответствия: `Studio 1.0` для исходных пресетов, `Photo 1.0` для сохранённой схемы 0.1.6, `Cycles prototype 0.1` с одним area light **160 W**, базовым окружением **0.48** и AgX. Эти числа не считаются физически эквивалентными интенсивности Three.js. Коэффициенты не должны переводиться в `.matvision` до визуального принятия.

Официальные источники: [Blender command-line rendering](https://docs.blender.org/manual/en/4.5/advanced/command_line/render.html), [Blender GPU rendering](https://docs.blender.org/manual/en/4.5/render/cycles/gpu_rendering.html), [three-gpu-pathtracer](https://github.com/gkjohnson/three-gpu-pathtracer). Поставка Blender и изображения пользователя остаются локальными.
